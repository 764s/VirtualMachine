## 一、设计目标

### 1.1 核心目标
- 复刻 KOF98 核心机制：角色、技能、碰撞、战斗
- 探索 FFVM 在实际游戏中的应用点
- 为将来的 ECS 重构奠定基础

### 1.2 约束
- 不要求 ECS（当前为初期探索）
- 视图层可替换（先实现不依赖 Unity 的版本）
- 所有角色状态（待机、走跑、受击、防御、抓投、死亡、技能、剧情）统一在技能系统下实现
- 为 FFVM 留出明确的应用点

## 二、架构决策

### 2.1 帧执行模型

选择固定顺序多 Pass 模型（非 ECS System 排序）：

```
Scene.Step()
  → 命令处理
  → 输入应用
  → 技能状态转换 (deactivate → activate)
  → 帧进入 (碰撞框更新)
  → 物理积分
  → 推箱解析
  → 技能处理 (VM Tick)
  → 战斗结算
  → 效果更新
  → 弹幕更新
  → 自动朝向
  → 回合检查
```

**理由**：
- 时序要求明确（多个 character.run 循环）
- 与参考架构一致
- 物理必须在碰撞检测前完成
- 技能处理（VM Tick）产生的命中事件在战斗结算阶段统一处理

### 2.2 技能系统 = 状态机

所有角色行为都是技能：
- 待机 (Idle): 循环技能，优先级最低
- 走跑 (Walk/Run): 循环技能，可被攻击打断
- 攻击 (Attack): 有限帧技能，VM 驱动
- 受击 (Hit): 由宿主切换层在检测到伤害后激活
- 防御 (Block): 条件驱动（方向 + 距离 + 对手攻击状态）
- 死亡 (Death): 系统优先级

技能转换逻辑：
```
TryDeactivateSkill() → 当前技能帧耗尽或被打断？
TryActivateSkill()   → 遍历技能目录，找最高优先级满足条件的技能
```

### 2.3 VM 应用分级

参照 C0 部署架构的"稳赚/模糊/稳亏"分析：

| 应用点 | 判定 | 理由 |
|--------|------|------|
| 攻击技能（飞燕旋风腿等） | ✅ 稳赚 | ≥10行、含 yield、多帧生命周期 |
| AI 决策 | ✅ 稳赚 | 持续运行、含 wait、需要断点调试 |
| 持续效果器（DOT、Buff） | ✅ 稳赚 | 独立生命周期、需 defer 清理 |
| 弹幕行为 | ✅ 稳赚 | 多帧飞行、命中检测、自定义轨迹 |
| 受击反应 | ⚠️ 模糊 | 简单但可能需要调试 |
| 纯数值计算（伤害公式） | ❌ 稳亏 | ≤3行、纯条件→调用 |

### 2.4 视图层设计

接口化设计，当前实现为控制台 ASCII 渲染：

```
IGameView
  Initialize(scene)    — 初始化渲染资源
  Render(scene)        — 每帧渲染（只读场景状态）
  Shutdown()           — 释放资源
```

控制台视图显示：
- HUD：HP条、能量条、回合/帧信息
- 场景：字符网格 + 角色标记 + 碰撞框轮廓
- 调试：位置、速度、朝向、当前技能

将来切换为 Unity 视图时，只需实现 `IGameView` 接口。

### 2.5 碰撞框系统

碰撞框由技能动作定义（`SkillDef.CollisionFrames`）：

```
CollisionBoxFrame:
  - StartFrame, EndFrame    帧范围
  - BoxType                 Hurtbox / Hitbox / Blockbox / Pushbox
  - GroupId                 攻击组 ID（用于互斥判定）
  - Box (FRect)             AABB（相对角色锚点）
```

`SkillManager.EnterFrame()` 每帧根据当前技能帧更新角色的碰撞框。

## 三、扩展点

### 已预留的扩展点

1. **AI 脚本化**：`IAIController` 接口 → 将来用 VM 实例替代 `SimpleAI`
2. **弹幕脚本化**：`ProjectileData.VMInstanceId` → 复杂弹幕用 VM 驱动
3. **效果器脚本化**：`EffectInstance.VMInstanceId` → 持续效果用 VM 驱动
4. **Unity 视图**：`IGameView` 接口 → 实现 `UnityGameView`
5. **帧同步/回滚**：`GameScene` 所有状态可序列化 → `SaveState`/`LoadState`
6. **网络对战**：`SceneInput` 可网络传输 → 确定性模拟
7. **ECS 重构**：当前类结构可直接映射为 ECS Component

## 四、风险与待决

| ID | 风险 | 影响 | 缓解 |
|----|------|------|------|
| R1 | ExecuteInstance 不是 VMWorld 公开 API | VMBridge 无法逐实例 Tick | 需要确认 API 可用性，可能需 VMWorld 扩展 |
| R2 | 控制台输入非阻塞读取有限 | P1 输入体验差 | 将来切换为 Unity 或 SDL 输入 |
| R3 | float 非确定性 | 帧同步不可靠 | 开发期使用 float，发布期切换 Fix64 |
| R4 | 碰撞框数据硬编码 | 维护困难 | 将来从 JSON/资源文件加载 |
