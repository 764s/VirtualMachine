| FS5 | 别名包含 (Aliased Include) | include "x" as Alias |

6. **跨文件struct字段引用** — 仅有同文件字段引用测试
7. **传递包含引用查找** — 仅有传递定义跳转

## 七、审查发现的已知限制

通过 DX12 测试运行，发现并记录了以下已知限制：

| ID | 问题 | 严重度 | 说明 |
|----|------|-------|------|
| KL-01 | 参数引用不包含声明位置 | 低 | `textDocument/references` 在参数上仅返回函数体内的使用，不包括参数声明本身 |
| KL-02 | 参数重命名不支持 | 中 | `textDocument/rename` 对参数返回 null，无法重命名参数名 |
| KL-03 | struct字面量名不计入struct重命名 | 低 | `Vec2 { x: 1 }` 中的 `Vec2` 可能不被 rename 编辑覆盖 |
| KL-04 | private 不过滤跨文件补全 | 中 | `private func` 仍出现在 include 文件的 completion 列表中 |
| KL-05 | 同名变量引用不隔离作用域 | 低 | 内外层同名 `var x` 的 references 返回所有同名引用（5个），未按作用域隔离 |

这些发现为后续 LSP 改进提供了明确方向。

## 九、审查总结

### 9.1 完成内容

1. **三维覆盖矩阵**（§一~§五）：10 种符号类型 × 8 种 LSP 功能 × 6 种文件范围，对现有 540 个 LSP 测试逐一映射，标注 ✅ 已覆盖 / ❌ GAP。
2. **25 个新测试用例**（§八 DX12-01~25，50 个断言点）：
   - Phase1（DX12-01~06）：表达式上下文——赋值右侧、if 条件、for 循环、return、嵌套调用 `f(g())`、struct 字面量字段值
   - Phase2（DX12-07~09）：参数导航——定义跳转、引用查找、重命名
   - Phase3（DX12-10~16）：跨文件高级——传递包含引用/补全、struct/enum 跨文件重命名、字段引用、模块变量跨文件导航
   - Phase4（DX12-17~22）：控制流——if/else 分支变量引用、while 条件、for 内符号、嵌套字段链 `o.inner.val`、调用参数位置、同名变量作用域
   - Phase5（DX12-23~25）：可见性——private 过滤、override 定义跳转、3 级深链传递
3. **5 个已知限制**（§七 KL-01~05）：发现 LSP 实现层的功能缺口，为后续改进提供精确方向。

|------|------|
| 三维矩阵审查 | 系统性覆盖分析而非靠直觉找遗漏，能发现隐蔽空白 |
| 跨文件高级场景 | DX12-10（传递引用）、DX12-16（模块变量跨文件）、DX12-25（3 级深链）覆盖了日常使用但测试空白的场景 |
| 表达式上下文全覆盖 | Phase1 精准定位"符号出现在非声明、非顶层位置"的盲区，如 `return helper()`、`Vec2 { x: getX() }` |
| 发现即文档化 | KL-01~05 通过条件分支断言记录（不阻塞 CI 且不丢失信息） |

### 9.3 受限制的妥协处理

| 妥协 | 原因 | 理想做法 |
|------|------|---------|
| DX12-08 参数引用阈值 ≥2 | LSP 仅返回函数体内使用，不含参数声明位置（KL-01） | 修复 CollectReferencesWithOrigin 让参数声明也被收集，断言 ≥3 |
| DX12-09 参数重命名走"已知限制"路径 | HandleRename 对参数返回 null（KL-02） | 修复 HandleRename 添加参数符号类型支持 |
| DX12-12 struct 重命名阈值 ≥2 | struct 字面量名 `Vec2 { ... }` 未被 rename 覆盖（KL-03） | 修复 struct rename 收集逻辑包含 StructLiteralExpr.TypeName |
| DX12-22 同名变量未断言隔离 | 内外层同名 `var x` 的 references 都返回全部同名引用（KL-05） | 修复 references 实现基于作用域的精确匹配 |
| DX12-23 private 过滤走"已知限制"路径 | `private func` 仍出现在跨文件补全中（KL-04） | 修复 completion 过滤 IsPrivate && OriginFile != currentFile |

**共同模式**：发现了真实问题，但本次任务为"测试审查"非"Bug 修复"，故调整断言为当前行为下限，同时标注偏差根因。修复需求已提交串行计划 → DX13~DX16。

### 9.4 想做但没做的

| 想做的 | 未做原因 |
|-------|---------|
| 修复 KL-01~05 的 LSP 实现缺陷 | 任务范围为审查而非修复；5 个 KL 涉及多个 walker 子类，改动面大 → 已拆分为 DX13~DX16 |
| 别名包含导航测试（`include as`） | 别名 LSP 导航实现复杂度高，可能发现更多底层问题 → 留作 IA-F1 展望项 |
| 增量编辑场景（添加/移除 include 后符号可见性变化） | 需多次 didChange + 补全列表差异验证，单测成本远高于快照测试 |
| 语法错误下的降级导航测试 | 需理解 error recovery 边界，优先级 P2 |
| defer/using/yield/wait_for 块内符号导航 | 日常使用频率较低，优先级 P2 |
| 性能/规模测试（50+ 文件项目） | 需搭建复杂测试夹具，属不同测试层次 |
