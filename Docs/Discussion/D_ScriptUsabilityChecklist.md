## 一、检验标准（35 项 × 7 大类）

> 以下标准在了解 FFScript 具体实现**之前**制定，来自资深脚本语言使用者对"合格脚本语言"的通用要求。

### A. 语法与可读性（Syntax & Readability）

| # | 检验项 | 说明 |
|---|--------|------|
| A1 | 语法一致性 | 声明方式（变量、函数、结构体）是否遵循统一范式，无"特例语法" |
| A2 | 最少关键字 | 关键字数量适当（≤25），不需要记忆大量保留词 |
| A3 | 操作符完备 | 算术、比较、逻辑、位运算齐全，优先级符合直觉 |
| A4 | 括号/大括号规则清晰 | 条件语句、循环、函数体的大括号规则一致、无歧义 |
| A5 | 注释支持 | 至少支持行注释，最好有文档注释 |

### B. 类型系统与变量（Types & Variables）

| # | 检验项 | 说明 |
|---|--------|------|
| B1 | 静态类型 | 编译期类型检查，避免运行时类型错误 |
| B2 | 类型标注清晰 | 变量声明时类型信息显式且可读 |
| B3 | 结构体/复合类型 | 支持用户自定义复合数据类型 |
| B4 | 枚举 | 支持命名常量集合 |
| B5 | 常量 | 支持编译期常量声明 |
| B6 | 作用域清晰 | 变量的作用域规则明确（块级、函数级、模块级） |

### C. 控制流与函数（Control Flow & Functions）

| # | 检验项 | 说明 |
|---|--------|------|
| C1 | if/else 完整 | 支持 if/else if/else 链 |
| C2 | 循环完整 | 支持 while 和 for 循环 |
| C3 | 函数定义与调用 | 函数可带参数、可带返回值、可递归 |
| C4 | 可选参数 | 函数参数可有默认值 |
| C5 | 提前返回 | 函数内任意位置可 return |

### D. 模块化与代码组织（Modularity）

| # | 检验项 | 说明 |
|---|--------|------|
| D1 | 多文件支持 | 可将代码拆分到多个文件 |
| D2 | 可见性控制 | 有 public/private 或等效机制防止命名泄漏 |
| D3 | 命名冲突处理 | 多文件合并时同名符号有明确处理规则 |
| D4 | 循环依赖检测 | 文件间循环引用有编译期检测 |

### E. 错误处理与编译器诊断（Error Handling & Diagnostics）

| # | 检验项 | 说明 |
|---|--------|------|
| E1 | 编译期错误信息有行号列号 | 报错可精准定位 |
| E2 | 类型不匹配报错 | 赋值/参数类型错误编译期拒绝 |
| E3 | 未定义符号报错 | 引用未声明的变量/函数/类型有编译错误 |
| E4 | 资源清理强制检查 | 如果语言有资源管理机制，应有遗忘清理的编译期提醒 |
| E5 | 不可达代码/死代码检测 | 至少不会因死代码导致运行时怪异行为 |

### F. 开发工具链（Tooling & DX）

| # | 检验项 | 说明 |
|---|--------|------|
| F1 | LSP 支持 | 代码补全、悬停提示、跳转定义、查找引用 |
| F2 | 语义染色 | 编辑器中有语法高亮 + 语义级别的颜色区分 |
| F3 | 重命名重构 | 全项目范围的安全重命名 |
| F4 | 调试器支持 | 断点、单步、变量查看 |
| F5 | CLI 工具 | 命令行编译、运行、检查 |

### G. 常见陷阱/坑检验（Common Pitfalls）

| # | 检验项 | 说明 |
|---|--------|------|
| G1 | 语法容错 | 常见的"随手多写/少写"（尾逗号、分号等）不应导致灾难性后果（如无限循环、崩溃） |
| G2 | 自增/自减缺失的补偿 | 若没有 `i++`，至少 `i = i + 1` 应在编译器层有等效优化 |
| G3 | 同名遮蔽规则 | 局部变量与模块变量同名时，规则明确且不易出错 |
| G4 | 空值安全 | 没有 null 或有明确的零值语义，避免空指针类 bug |
| G5 | 字符串运行时拼接 | 如果不支持运行时拼接，应有编译期拒绝机制而非运行时静默失败 |

## 二、验证结果

### A. 语法与可读性

| # | 检验项 | 结果 | 证据 |
|---|--------|------|------|
| A1 | 语法一致性 | ✅ 通过 | Go 风格统一范式：`var x: type = val`、`func f(a: type): ret {}`、`struct S { f: type }`。声明方式高度一致 |
| A2 | 最少关键字 | ✅ 通过 | 20 个关键字 + 2 个注解（[FFS_Syntax.md §2.2](../Reference/FFS_Syntax.md)），控制在合理范围内 |
| A3 | 操作符完备 | ✅ 通过 | 算术/比较/逻辑/位运算（`& \| ^ ~ << >>`）齐全，13 级优先级，符合 C 系语言直觉（[FFS_Syntax.md §2.3](../Reference/FFS_Syntax.md)） |
| A4 | 括号/大括号规则 | ✅ 通过 | 条件不需括号、大括号必须有，规则简单一致 |
| A5 | 注释支持 | ✅ 通过 | 行注释 `//` + 文档注释 `///`（含 `@param`/`@return`），不支持块注释 `/* */` |

### B. 类型系统与变量

| # | 检验项 | 结果 | 证据 |

| B3 | 结构体 | ✅ 通过 | `struct` 支持嵌套、值语义（赋值即复制），编译期递归拍平（[FFS_Syntax.md §3.2](../Reference/FFS_Syntax.md)） |
| B4 | 枚举 | ✅ 通过 | `enum Color { RED, GREEN, BLUE }`，支持显式值、自动递增、位域（Lang-13，[FFS_Syntax.md §4.5](../Reference/FFS_Syntax.md)） |

| B6 | 作用域清晰 | ✅ 通过 | 块级作用域明确。局部变量不可与模块变量同名（编译错误），消除遮蔽歧义 |

### 特别亮点

- **零 null 设计**：从语言层面消灭最常见的运行时错误类别
- **资源清理强制检查**：`using` + `defer` + 编译器强制检查 = 不可能忘记清理
- **Parser 鲁棒性**：B002 修复后全面 progress guard，不会因语法错误导致无限循环
- **LSP 成熟度**：652 项 LSP 测试覆盖，含作用域隔离、参数重命名、跨文件符号等高级场景
- **同名遮蔽零容忍**：编译期禁止局部/模块变量同名，从根源消灭遮蔽 bug

## 四、改进建议（按优先级）

### 🔴 高优先级（影响日常体验）

#### UC-1: 未使用变量/参数警告（对应 E5）

当前编译器有 DCE 优化但不向用户报告"声明了变量但未使用"。这是脚本编写中最高频的 typo 类 bug 来源——特别是重构后忘删旧变量、或拼错变量名。

**建议**：编译器或 LSP 诊断增加 `unused variable` / `unused parameter` warning。可用 `_` 前缀约定标记"有意不使用"（Go 惯例）。

**复杂度**：⭐⭐（编译器已有寄存器生命周期分析 F4，可复用读写追踪）

#### UC-2: break / continue 语句

EBNF 与关键字表确认 ffs 没有 `break` 和 `continue`。复杂循环必须用额外 flag 变量 + 条件判断模拟退出，降低可读性。实际脚本中（如 [skill_light_punch.ffs](../../KOF98/Scripts/skill_light_punch.ffs) 的 `hitDone` flag）已出现此 workaround。

**建议**：增加 `break` 和 `continue`。对帧循环（`while f < N { ... yield }`），`break` 是提前结束技能阶段的自然表达。

**复杂度**：⭐⭐（编译器需处理循环出口跳转 + Cleanup 栈展开）

### 🟡 中优先级（改善体验上限）

#### UC-3: 块注释 `/* ... */`

当前只支持行注释 `//`。大段临时禁用代码（调试常见操作）需逐行加 `//`，效率低。

**建议**：Lexer 层支持 `/* ... */`。

**复杂度**：⭐（Lexer 改动极小，不影响运行时）

#### UC-4: 复合赋值运算符 `+=` `-=` `*=` `/=`

当前 `i = i + 1` 是唯一写法。虽然 `for` 模式已优化为 FORLOOP，但在非 for 场景（如 `hp = hp - damage`）中，`hp -= damage` 更简洁且不容易因重复写变量名而 typo。

**建议**：Parser 层作为语法糖展开为 `lhs = lhs op rhs`，不需要新 OpCode。

**复杂度**：⭐（纯 Parser 语法糖）

#### UC-5: 字符串操作的专用编译期错误（对应 G5）

当用户尝试对 string 做不支持的操作（如拼接）时，当前依赖间接类型检查报错。对从其他语言迁移的用户，一个明确的"FFScript 不支持运行时字符串拼接，请使用 Syscall"错误消息会大大降低困惑。

**建议**：类型检查层对 string 类型的 `+` 运算检测到时发出专用错误消息。

**复杂度**：⭐（编译器类型检查一处特判）

### 🟢 低优先级（锦上添花）

#### UC-6: 定长数组

当前没有数组，变长数据完全依赖 Syscall 委托宿主。这是架构硬约束（零 GC + 定长寄存器）下的合理权衡，但定长数组（编译期大小确定）可提升表达能力。

**建议**：未来考虑 `var arr: int[8]`，编译期拍平为连续寄存器段（与 struct 拍平方式一致），零 GC 零违规。

**复杂度**：⭐⭐⭐（Parser + 编译器 + 运行时寄存器布局）

#### UC-7: Range-for 语法糖

当前 for 只有 C 风格三段式。`for i in 0..10` 在帧循环场景中更简洁。

**建议**：Parser 层展开为 `for var i: int = 0; i < 10; i = i + 1`。

**复杂度**：⭐⭐（Parser 语法糖 + FORLOOP 识别适配）
