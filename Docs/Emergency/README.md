# 紧急独立任务区

> **定位**：独立于串行计划的紧急修复通道。恶性缺陷和影响深远缺陷在此跟踪、修复，
> 修复完成后将剩余次优先级任务归还串行计划或展望。
>
> **工作流版本**：v1（2026-04-04 初建，执行中根据实践调整优化）

---

## 工作流定义

```
┌─────────────────────────────────────────────────────┐
│  紧急独立任务区 工作流                                │
│                                                     │
│  1. 发现 → 分类                                      │
│     ├─ 🔴 恶性缺陷（阻塞使用 / 数据错误）→ 立即修复     │
│     ├─ 🟠 影响深远缺陷（安全隐患 / 架构陷阱）→ 紧急修复 │
│     └─ 🔵 次优先级（优化 / 美化 / 待验证）→ 暂存        │
│                                                     │
│  2. 修复（🔴 → 🟠 严格顺序）                          │
│     ├─ 每个缺陷独立文件 E{NNN}_{title}.md              │
│     ├─ 文件内含：描述、修复计划、风险点、完成标准         │
│     └─ 修复完成 → 更新状态 → 风险点纳入总览             │
│                                                     │
│  3. 回收                                             │
│     ├─ 🔴🟠 全部修复后 → 🔵 评估                       │
│     ├─ 符合串行计划 → 纳入 VM_Summary.md §七-B          │
│     ├─ 符合展望 → 纳入 Outlook_And_Risks.md             │
│     └─ 新增风险 → 纳入 Outlook_And_Risks.md §六         │
│                                                     │
│  4. 清空后本区域归于待命状态                             │
│                                                     │
│  ※ 串行计划在紧急任务修复期间暂停推进                    │
└─────────────────────────────────────────────────────┘
```

### 工作流规则

1. **准入**：只有**阻塞使用**或**静默产生错误结果**的缺陷可进入 🔴；**架构隐患**或**影响所有后续开发者**的问题可进入 🟠
2. **修复顺序**：🔴 全部修复完毕后再处理 🟠
3. **串行计划暂停**：紧急任务修复期间，串行计划（§七-B）暂停推进
4. **风险回流**：每个修复方案的风险点在修复完成后统一纳入 `Outlook_And_Risks.md`
5. **次优先级回收**：🔵 任务在缺陷全部清除后逐一评估，分流到串行计划或展望
6. **工作流演进**：每次紧急任务区从激活到清空的完整周期后，回顾工作流本身，记录改进
